## 目标

产出错误码分段表定稿：7 个模块段 + 公共错误码，作为接口清单（T5）与后续后端实现（`BusinessException`）的错误码唯一依据。

## 输入依赖

- `.qoder/rules/api-contract.md`（错误码分段已定义基线：1000-1099 公共 / 2000-2099 用户 / 3000-3099 商品 / 4000-4099 订单 / 5000-5099 售后 / 6000-6099 商家 / 7000-7099 管理员）
- T1 状态机枚举表（状态相关错误码的取值来源）
- 启动指导书第 6 节（接口与权限规则）

## 工作步骤

1. 按 7 段列出错误码表，每段至少覆盖：参数类错误、资源不存在、状态不允许操作、权限不足。
2. 公共段（1000-1099）先定 5 个基准码：1001 参数错误、1002 未登录、1003 无权限、1004 资源不存在、1005 系统错误。
3. 各模块段细化，示例方向：
   - 用户段：注册重名、密码错误、地址不存在
   - 商品段：商品不存在/已下架、库存不足、类目不存在
   - 订单段：订单不存在、状态不允许该操作、购物车项无效、地址不存在、库存不足
   - 售后段：售后单不存在、订单不可退款、重复退款申请
   - 商家段：店铺未通过审核、非本店数据
   - 管理员段：审核参数缺失、审核原因必填
4. 每个错误码注明：码值、中文 message、触发场景、HTTP 返回形式（统一 `{code, message, data, total}`，HTTP 200）。
5. 与 T1 状态机核对：所有"状态不允许操作"类错误码对应的状态取值必须一致。
