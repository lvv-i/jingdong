# T5 接口清单 v1.0（汇总 B/C/D 接口需求）

> 成员 A ｜ 计划 Day 2-3 ｜ 状态：⬜ 未开始
> 关联 skill：`.qoder/members/member-a/skills/api-inventory.md`（A 专属）、`.qoder/skills/api-design.md`（团队共享）

## 目标

产出接口清单 v1.0：全量 API 列表（URL、方法、请求、响应、错误码、访问角色），v0.9 供联调试用，v1.0 定稿发布。这是第二阶段 A 写代码与 B/C/D 写前端调用的共同合同。

## 输入依赖

- B 的用户端接口需求清单、C 的后台接口需求清单、D 的移动端页面清单（Day 2 提交）
- T1 状态机枚举表、T3 错误码分段表、T4 JWT/RBAC 方案
- 启动指导书第 6 节（示例接口：公共商品、用户下单、商家处理、平台审核、个人中心、消息通知）

## 工作步骤

1. 收集 B/C/D 的接口需求清单，合并去重，按四个角色分组：
   - 公共（无需登录）：商品浏览、搜索、类目、注册、登录
   - 用户端：购物车、订单、模拟支付、售后、评价、地址、通知
   - 商家端（/api/merchant/）：商品发布/上下架、库存、订单发货、退款处理、店铺资料
   - 管理员端（/api/admin/）：商家审核、类目管理、商品巡检、争议介入、统计
2. 每个接口按模板填写：编号、模块、方法+URL、访问角色、请求参数/请求体、成功响应示例（统一返回格式）、可能错误码（来自 T3）、备注（状态流转/快照要求）。
3. 检查清单：
   - 统一返回格式 `{code, message, data, total}`；分页接口固定 `page/pageSize` 且 data 为 `{list, total}`
   - 每个接口标注访问角色与数据范围（对应 T4）
   - 涉及状态流转的接口标注"from → to"（对应 T1）
4. 发布 v0.9：发给 B/C/D 试用核对，收集反馈修订。
5. 发布 v1.0：在清单头部标注版本号、日期、变更记录，通知全员。
