# 03 错误码分段表

> 版本：v1.0 ｜ 作者：成员 A（后端核心）｜ 日期：2026-08-12
> 依据：`.qoder/rules/api-contract.md`（错误码分段基线） + T1 状态机枚举表（状态类错误码取值来源）
> 本表是 T5 接口清单与后端 `BusinessException` 实现的错误码唯一依据。

## 0. 分段总览

| 段 | 码值范围 | 归属 | 覆盖内容 |
|---|---|---|---|
| 公共 | 1000-1099 | Common | 参数、认证、权限、系统 |
| 用户 | 2000-2099 | User | 注册、登录、地址、资料 |
| 商品 | 3000-3099 | Product | 商品、类目、搜索 |
| 订单 | 4000-4099 | Order | 购物车、订单、模拟支付 |
| 售后 | 5000-5099 | Refund | 退款、售后 |
| 商家 | 6000-6099 | Merchant | 店铺、商家后台 |
| 管理员 | 7000-7099 | Admin | 审核、治理、统计 |

**统一返回信封**：所有接口（含业务错误）HTTP 200，返回 `{code, message, data, total}`；`code=200` 为成功。

## 8. 状态类错误码与 T1 状态机对照

| 错误码 | 对应状态机 | 涉及的合法取值（引用 T1 交付物） |
|---|---|---|
| 3002 商品已下架 | 商品状态机 | status ∉ {ON_SALE} 时用户端不可购买 |
| 3005 商品状态不允许 | 商品状态机 | 违反 T1 商品禁止流转清单（如 DRAFT→ON_SALE、OFF_SALE→ON_SALE） |
| 4002 订单状态不允许 | 订单状态机 | 违反 T1 订单禁止流转清单（如 COMPLETED→CANCELLED、PAID→CANCELLED） |
| 5002 订单状态不允许退款 | 售后业务规则 | 订单 status ∈ {PENDING_PAY, CANCELLED} 不可发起退款 |
| 5005 售后单状态不允许 | 售后状态机 | 违反 T1 售后禁止流转清单（如 REFUNDED→任意、MERCHANT_AGREED→CLOSED） |
| 6002 店铺未通过审核 | 商家入驻状态机 | audit_status ≠ APPROVED |
| 6003 店铺审核中 | 商家入驻状态机 | audit_status = PENDING_AUDIT |
| 6005 店铺已被驳回 | 商家入驻状态机 | audit_status = REJECTED |

## 9. 使用规则

1. **定义权**：错误码仅由后端（成员 A）定义；新增/修改错误码须更新本表并升版，同步通知 B/C/D。
2. **使用权**：前端只按 `code` 展示后端 `message`；可针对特定 code 做交互优化（如 1002 跳转登录），但不得自行解释 code 含义。
3. **抛出方式**：后端通过 `BusinessException(code, message)` 抛出，`GlobalExceptionHandler` 统一转换为 `{code, message, data, total}`；HTTP 状态保持 200（传输层错误除外）。
4. **命名规范**：后端枚举类 `ErrorCode`，常量命名 `UPPER_SNAKE_CASE`，如 `ORDER_STATUS_NOT_ALLOWED(4002, "订单状态不允许该操作")`。
5. **message 要求**：中文、面向用户可读；禁止暴露 SQL、堆栈、内部类名。
6. **码值约束**：不越段、不重复、不复用（已下线的码保留注释，不分配给新场景）。

## 10. 差异记录与决策

对照 `.qoder/rules/api-contract.md` 逐条核对：7 段范围与公共 5 个基准码（1001-1005）完全一致，无差异。
