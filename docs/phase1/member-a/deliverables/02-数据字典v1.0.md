**status 字段说明**：依据 `.qoder/rules/db-conventions.md`，纯链接表/日志表可省略 `status`（仍保留 id/created_at/updated_at/deleted_flag）；业务状态表必须含全部 5 个统一字段。本字典含 status 的表：users、merchant_shops、categories、products、orders、refund_requests、payment_records（共 7 张）。

## 1. 全局字段与命名规范（引自 db-conventions.md）

1. **统一字段**：业务表末尾固定 `id` BIGINT UNSIGNED 自增主键、`created_at`、`updated_at`（自动更新）、`status` VARCHAR(32)（业务状态表）、`deleted_flag` TINYINT 默认 0（软删除）。
2. **类型**：金额 DECIMAL(12,2)；数量/库存 INT UNSIGNED；status VARCHAR(32)；布尔 TINYINT(0/1)；长文本 TEXT。
3. **命名**：下划线小写；外键 `<entity>_id`；禁用缩写（quantity 不用 qty）。
4. **软删除**：业务表只软删，所有查询 `WHERE deleted_flag = 0`。
5. **索引**：外键、status、created_at、order_no 必须建索引。
6. **注释**：每表每列中文注释；status 注释列出全部取值（引用 T1 状态机枚举表）。
7. **快照**：order_items 必含 title_snapshot、price_snapshot；refund_requests 必含 reason、merchant_reply、admin_result。
8. **审核留痕**：merchant_shops 必含 audit_status、audit_reason；audit_logs 记录操作者角色。

## 4. 核查结论（对照 db-conventions 8 项强制核查）

| # | 核查项 | 结论 |
|---|---|---|
| 1 | 统一字段 id/created_at/updated_at/status/deleted_flag | ✅ 13 张表全部含 id/created_at/updated_at/deleted_flag；7 张业务状态表含 status，6 张纯链接/日志表按 rule 豁免 status |
| 2 | 快照 | ✅ order_items 含 title_snapshot、price_snapshot；orders 含 receiver_snapshot（收货快照，下单冻结） |
| 3 | 类型 | ✅ 金额 DECIMAL(12,2)；数量/库存 INT UNSIGNED；status VARCHAR(32)；布尔 TINYINT |
| 4 | 命名 | ✅ 全部下划线小写；外键 `<entity>_id`；无缩写 |
| 5 | 软删除 | ✅ 全部业务表含 deleted_flag，无物理删除计划 |
| 6 | 索引 | ✅ 外键、status、created_at、order_no/refund_no 全部建索引 |
| 7 | 注释 | ✅ 每表每列中文注释；7 个 status 字段注释列出全部取值（与 T1 状态机一致） |
| 8 | 审核留痕 | ✅ merchant_shops 含 audit_status/audit_reason；audit_logs 含 operator_role/target_type/action/remark |
