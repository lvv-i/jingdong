## 关键交互细节（体现"思考判断"的轮次）

### 轮次 1：双兼容解包模式（M3 期间）

- **问题**：后端契约在裸数组与 {list,total} 之间演变（A 的 772ddec 修复后），mobile-app 三处列表消费（cart.vue/address.vue/checkout.vue）面临新旧 jar 兼容问题。
- **AI 判断**：统一采用 `Array.isArray(data) ? data : (data && data.list) || []` 双兼容解包，无论后端返回哪种形态均可渲染；与 B 端 frontend-user 保持同一模式，四端行为一致。

### 轮次 2：H5 与小程序双端构建（X5 期间）

- **问题**：uni-app 需同时验证 H5 与微信小程序两套产物。
- **AI 判断**：H5 用 browser 实测 5 页交互；小程序用 `npm run build:mp-weixin` 验证构建产物 dist/build/mp-weixin 结构完整（app.json/pages 齐全），GUI 验收留待微信开发者工具安装后执行（已登记 backlog）。

### 轮次 3：联调观察项闭环（X-07 更新，2026-08-29）

- **问题**：A 提交 772ddec 后旧观察项（裸数组消费）作废，X-07 记录需与最新契约一致。
- **AI 判断**：更新 X-07 步骤 7/8 为双兼容模式、结论行补充观察项 3（A 契约修复）、§6 补双向闭环说明，保证交付物与代码事实一致。

### 轮次 4：截图的替代方案（2026-08-29）

- **问题**：browser 截图工具对全部页面固定超时（15s），X-09 要求的 M3 联调截图无法产出。
- **AI 判断**：改用 OS 级方案——枚举浏览器主窗口 GetWindowRect + CopyFromScreen 截取窗口区域保存 PNG，配合 Browser 子代理逐页导航，产出 index/cart/mine 三张真实联调页面截图。
