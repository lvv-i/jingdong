## 关键交互细节（体现"思考判断"的轮次）

### 轮次 1：U-012 拆单返回形态（W3 期间）

- **问题**：T5 v1.0 写 U-012 返回单对象 `{orderId, orderNo, status, payAmount}`，与"按商家拆单"备注矛盾。
- **AI 判断**：按拆单语义消费 `data.orders[]` 数组（Checkout.vue 遍历渲染多个子订单），并在 W-06 偏差总表登记 🔴 级偏差，提示 A 修订 T5 文档（v1.1 已闭环）。

### 轮次 2：幽灵错误码（W6 期间）

- **问题**：P-008 错误码 2005（收货地址不存在）与验证码登录语境不符；U-024 的 4005 同理。
- **AI 判断**：不照抄 T5 文档写死分支，对照后端 ErrorCode 枚举确认真实码（P-008 为 2003/2004、U-024 无 4005），JSDoc 标注"T5 笔误"，前端只按后端实际码处理。

### 轮次 3：裸数组 vs PageResult 的双兼容（M3 期间）

- **问题**：W6 核对时后端 U-003/U-008 返回裸数组（B 按裸数组消费）；A 随后提交 772ddec/fbe7b71 将契约改回 T5 的 {list,total}。旧前端遇新 jar 会挂。
- **AI 判断**：不赌 jar 版本，采用与 D 端一致的"双兼容解包"：`Array.isArray(data) ? data : (data && data.list) || []`，Cart/Checkout×2/AddressList 四处统一；U-018 单号提示取 `refundNo || refundId`。npm run build 验证通过后提交。

### 轮次 4：联调脚本路径纠偏（M3 期间）

- **问题**：接口级联调脚本首版把地址列表写成 `/user/addresses`，返回 1001；且登录路径误用 `/auth/login`、密码误用 123456。
- **AI 判断**：逐项核对前端 api 封装与 seed 注释（密码=账号名，DataInitializer 重置 BCrypt），修正脚本后全链路跑通（登录→商品→地址→购物车→下单→支付→退款→通知）。
