## 关键交互细节（体现"思考判断"的轮次）

### 轮次 1：统一返回 vs 分页约定（S3 期间）

- **问题**：T5 §0 约定分页 data 为 {list,total}，但个别列表接口（地址/购物车）早期实现为裸数组。
- **AI 判断**：裸数组违背统一契约，按 T5 约定改回 PageResult{list,total}（fbe7b71/772ddec），并同步通知 B/D 前端做双兼容过渡，避免旧前端挂死。

### 轮次 2：状态机校验全覆盖（S3 期间）

- **问题**：T1 定义 10+ 条流转，Service 层每处状态判断容易遗漏或放行错误流转。
- **AI 判断**：所有状态变更接口在 Service 层前置校验（如 approveMerchant 仅 PENDING_AUDIT、submitProduct 仅 DRAFT），校验失败抛 T3 对应错误码，禁止流转清单逐条反测。

### 轮次 3：M3 联调发现 2 处状态机缺口（2026-08-29）

- **问题**：实测发现 T1 3.2「REJECTED → PENDING_AUDIT 重新提交」与 T1 4.2「OFF_SALE → PENDING_ON_SALE 重新上架」两条流转无对应接口。
- **AI 判断**：新增 M-002b（POST /api/merchant/shop/resubmit，状态不符 1001，写 audit_logs RESUBMIT）；M-006 扩展为 DRAFT/OFF_SALE → PENDING_ON_SALE。打包部署后正反用例实测：驳回→重提→待审核 ✅、APPROVED 重提 1001 ✅、下架→重提→待上架→审核恢复 ✅。

### 轮次 4：H2 重启幂等缺陷（2026-08-29）

- **问题**：h2-schema.sql 无 IF NOT EXISTS，数据库文件已存在时重启报「Table users already exists」。
- **AI 判断**：schema 全部改 `CREATE TABLE/INDEX IF NOT EXISTS`（44 处）；本地运行配置 sql.init.mode 改 never（首次建库后不重跑 seed，避免重复插入）；验证重启后种子账号哈希 0 重置、联调数据完整保留。
