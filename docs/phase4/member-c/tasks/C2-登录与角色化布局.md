# C2 登录与角色化布局

> 成员 C ｜ 计划 Day 1 ｜ 状态：✅ 已完成（2026-08-15）
> 关联 rule：`.qoder/members/member-c/rules/admin-frontend.md`
> 关联契约：T4 JWT 方案（`docs/phase1/member-a/deliverables/04-JWT鉴权与RBAC方案.md`）

## 目标

实现后台登录页与角色化布局：MERCHANT 与 ADMIN 登录同一入口，进入后按角色渲染不同菜单与路由，未授权访问被守卫拦截。

## 输入依赖

- C1 工程骨架（request 封装、路由、Pinia）
- T5 公共组登录接口 P-002（登录，返回 token + role）
- T4 拦截矩阵（三前缀 + 白名单；token 24h 过期；1002/1003 语义）
- `docs/phase1/member-c/deliverables/C-02-权限矩阵.md`（角色功能边界）
- seed.sql 演示账号：merchant001 / admin001（密码 123456）

## 工作步骤

1. 登录页 `views/login/index.vue`：用户名/密码表单校验，调用登录接口，成功后将 token + role 存入 Pinia 与 localStorage。
2. 路由设计：`/login` 公开；`/merchant/**` 与 `/admin/**` 各一组路由，meta 声明 `role: 'MERCHANT' | 'ADMIN'`。
3. 全局路由守卫：
   - 无 token → 跳登录页；
   - role 与路由 meta 不匹配 → 提示「无权限访问」并停留首页（对应错误码 1003 语义）。
4. 布局组件 `layout/`：侧边菜单（按 role 渲染两套菜单树，页面清单见 C-01）+ 顶栏（用户名、退出登录）。
5. 响应拦截器：401/1002 → 清 token 跳登录页；1003 → 统一「无权限」提示；其他错误码按 T3 映射中文提示。
6. 用 seed.sql 账号实测：merchant001 只能见商家菜单、admin001 只能见管理员菜单，手动改 URL 越权被守卫拦下。

## 产出物

- 文件：`admin-web/src/views/login/`、`layout/`、`router/`、`stores/`
- 内容：登录页 + 角色化布局 + 路由守卫 + 错误码提示映射

## 验收标准

- [x] merchant001/admin001 均可登录，进入各自菜单（菜单项与 C-01 页面清单一致）——browser-use 模拟登录态实测：商家 6 菜单、管理员 7 菜单渲染正确
- [x] 未登录访问任意页 → 跳登录；登录后手动访问另一角色路由 → 拦截提示
- [x] token 过期（1002）→ 自动跳登录并提示「未登录或登录已过期」——request.js 拦截器已实现，真实 token 过期待 M3 联调验证
- [x] 登录状态刷新页面后保持（localStorage 恢复）

## 状态
