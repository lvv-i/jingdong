# Rule (D专属): 测试基线与验收检查单

## Scope

适用于成员 D 兼任的测试/文档职能：第四阶段移动端自测、第五阶段全端回归与联调验收。

## 固定测试口径（强制）

1. 测试账号一律使用 D-02 方案固定账号：user001/user002/merchant001/merchant002/admin001（密码同账号），禁止随意注册新账号演示。
2. 短信验证码 demo 固定 123456；验证码 60 秒限频必须可测。
3. 联调地址统一 `http://localhost:8080`；各端代理指向该地址。
4. 演示路径可复现：使用种子数据走固定链路（D-02 第 2 节），保证每次演示结果一致。

## 测试三向覆盖（强制）

1. **正向**：T1 全部合法流转必须全跑通（订单 5 态、售后 6 态、商品 4 态、入驻 3 态）。
2. **负向**：T1 全部禁止流转必须被后端拒绝并返回正确错误码。
3. **边界**：库存 0（4006）、价格变化（4007）、重复支付（4008）、金额超实付（1001）、地址上限（2006）、验证码限频（1007）。

权限测试按 C-02 权限矩阵：未登录 1002、越权 1003。

## 验收检查单（P0/P1，来自启动指导书第 8 节）

- [ ] 登录与权限：五个端只能看到自己的菜单和数据范围，越权请求被后端拒绝
- [ ] 商品链路：商家发布后用户端可见，下架后立即不可见
- [ ] 下单链路：购物车 → 支付 → 待发货状态变化正确
- [ ] 履约链路：商家发货、用户确认收货、订单完成可连通
- [ ] 退款链路：用户申请、商家处理、管理员介入的结果完整保留
- [ ] 移动端构建：App 和小程序从同一套 uni-app 代码输出
- [ ] 数据一致性：刷新页面后订单、售后、库存状态不乱
- [ ] 空状态处理：无数据时页面不空白、不报错、有提示（P1）
- [ ] 演示可复现：启动脚本和初始化数据完整，换机器也能跑

## 记录要求（强制）

1. 每条测试用例必须落表（用例编号/场景/步骤/期望/实际/通过/备注），通过与否都要记录。
2. AI 交互逐轮记录（提问原文/AI 回复/思考判断/下一轮调整），对应作业评分 30 分。
3. 联调记录含接口版本号与结论；异常与处理过程如实记录。
4. 发现 bug 走 `fix/` 分支修复，回归测试通过后合入 `develop`。

## 禁止事项

- 禁止只记录"测试通过"而无用例明细
- 禁止用临时注册账号做演示（破坏可复现性）
- 禁止在未核对 D-02 与种子数据一致性的情况下宣布测试通过
