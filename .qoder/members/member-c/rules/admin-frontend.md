# rule: admin-frontend（后台前端规范）

> 成员 C 专属 ｜ 约束 `admin-web/` 工程 ｜ 用于 C2/C5
> 优先级：团队 `.qoder/rules/` > 本 rule > 个人临时想法

## 1. 工程约束（强制）

- 商家与管理员**共用一个 Vue 3 工程** `admin-web/`，禁止拆成两个工程。
- 按角色分菜单与路由：`/merchant/**` 与 `/admin/**` 两组路由，路由 meta 必须声明 `role`。
- 目录：`src/views/merchant/`、`src/views/admin/`、`src/views/login/`、`src/api/`（merchant.js/admin.js/auth.js）、`src/utils/status.js`（状态映射唯一来源）。
- 状态值、状态中文名、状态颜色只允许在 `src/utils/status.js` 定义一次，页面一律引用，禁止散落硬编码。

## 2. 状态按钮显隐（强制，依据 T1 状态机）

- 所有状态操作按钮必须按 `status.js` 状态映射 + T1 合法流转用 `v-if` 控制显隐。
- 禁止出现 T1 禁止清单中的操作入口（即使后端会拒绝，前端也不得渲染）。
- 审核/裁决/拒绝/下架类操作按钮在弹窗内完成，原因/回复字段：
  - `auditReason`：驳回必填、通过可选（A-002/A-003/A-009/A-011/A-012）
  - `reply`：商家同意/拒绝必填（M-013/M-014）
  - `adminResult` + `agree`：管理员裁决必填（A-015）
  - `shippingNo`：发货必填（M-011）

## 3. 越权与错误提示（强制，依据 C-02 权限矩阵）

- 前端只做按钮隐藏与路由拦截，**真正的权限判断在后端**；前端不因隐藏按钮而省略后端返回 1003 的提示处理。
- 错误码提示文案映射（T3）必须集中在 `src/utils/request.js`，页面不重复定义：
  - 1001 参数错误 ｜ 1002 未登录或登录已过期（触发跳登录） ｜ 1003 无权限访问 ｜ 1004 资源不存在 ｜ 1005 系统错误
  - 6xxx 商家域错误（6001 无店铺 / 6002 店铺未通过审核 等，按 T3 原文）
  - 7xxx 管理员域错误（7001/7002/7005 等，按 T3 原文）
- 商家登录态下若后端返回 6001/6002/6003，页面需给出引导文案（去提交入驻 / 等待审核），不裸弹错误码。

## 4. 数据展示（强制）

- 金额一律两位小数展示；订单号/退款号原样展示；买家昵称用后端脱敏后的 `userName`，前端不二次加工。
- 商家店铺数据只能来自本店接口（M 组），禁止调用 A 组接口取数；管理员页面同理只调 A 组（公共只读接口除外）。
- 列表分页遵循 api-contract：请求 `page/pageSize`，渲染 `list/total`。

## 5. 体验细节（建议，对应作业"体验优化"）

- 空状态：`el-table` empty 插槽（插画 + 引导文案），无数据不空白不报错。
- 长等待提示：售后 REFUNDING 超期、入驻 PENDING_AUDIT 超期时，页面给出等待时长与下一步引导（对应状态机"平台介入"入口条件）。
- 敏感操作二次确认：禁用用户（A-017）、强制下架（A-009）、裁决退款（A-015）操作前 `ElMessageBox.confirm`。
