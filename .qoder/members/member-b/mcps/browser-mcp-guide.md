# MCP (B专属): 用户端浏览器验证指南

> 团队已配置 2 个 MCP（browser-use、genui），本文件说明成员 B（用户网页端）如何利用它们辅助第四阶段页面开发与验证。

## 1. browser-use —— 页面端到端验证

适用任务：W1-W5 每个页面完成后的交互验证、全链路自测（W5）

- **验证页面流程**：启动前端 dev server 后，用浏览器走「首页 → 搜索 → 详情 → 加购 → 结算 → 下单 → 支付」链路，截图存档到 `docs/phase4/member-b/deliverables/`。
- **检查网络请求**：`list_network_requests` 核对每个请求的 URL、参数、`Authorization` 头、响应 `{code, message, data, total}` 是否符合 T5 契约。
- **验证按钮显隐**：在固定测试订单（D-02 方案）上，核对 PENDING_PAY/SHIPPED/COMPLETED 等状态下的按钮显隐与 T1 状态机一致。
- **验证错误提示**：触发库存不足、重复支付、越权等场景，确认 toast 文案与 T3 错误码一致（如 4006/4008）。
- **验证登录态**：未登录访问 `/cart` 应被守卫拦截跳 `/login`；token 过期后任意请求应自动跳登录。
- 用法细节见 `.qoder/mcps/browser-use.md`（团队共享说明）。

## 2. genui —— 页面原型参考

适用任务：W1 布局骨架、W2-W5 复杂页面（购物车/结算/订单详情）的布局草图

- **页面原型**：调用 `load_guidelines`（模块选 `mockup`）后，用 `show_widget` 生成页面布局参考，再落实到 Element Plus 组件实现。
- 原型仅作参考，最终以 B-01 页面清单 + Element Plus 规范为准。

## B 的使用约定

1. MCP 服务端由团队统一配置，B 不重复安装。
2. browser-use 验证使用 D 提供的固定测试账号（user001 等），不得临时改数据破坏演示基线。
3. 验证截图按任务归档：`docs/phase4/member-b/deliverables/W-0x-*.md` 中引用截图文件。
4. 发现接口行为与 T5 不符时，先记录「接口编号 + 现象 + 期望」，向 A 提交联调问题，不自改后端。
# MCP 使用约定（B专属）: browser-use 端到端页面验证

> 团队 MCP（browser-use / genui）如何服务于成员 B 的用户网页端开发与验收。

## browser-use 用于端到端验证（W2-W5）

**前提**：后端 8080 已启动（M3 里程碑，MySQL 8 环境就绪后）+ 用户端 dev server 已启动。

### 验证场景与验收点

| 场景 | 步骤要点 | 通过标准 |
|---|---|---|
| 注册登录 | 注册新用户 → 登出 → 密码登录 → 短信登录（123456） | 三种方式均成功进入首页 |
| 浏览搜索 | 首页 → 搜索关键词 → 切 sort 价格升 → 进详情 | 列表顺序变化、详情信息完整 |
| 购物下单 | 加购 → 购物车勾选 → 结算 → 提交订单 | 订单状态 PENDING_PAY，跳转详情 |
| 模拟支付 | 订单详情点支付 | 状态变 PAID，paymentNo 展示 |
| 售后全流程 | 发起退款 → 撤销 → 再发起（商家拒绝后）→ 申请介入 | 按钮随状态显隐正确 |
| 空状态 | 新注册用户访问购物车/订单/通知 | 均有空提示，无空白报错 |

### 使用约定

1. 每次验证先截图存档（按 `docs/phase4/member-b/deliverables/W-xx-*.md` 引用），截图配文字说明（对应作业评分"使用示例"要求）。
2. 发现页面 bug 先本地排查，确认非契约问题后记录到联调记录再反馈 A。
3. 验证用账号固定使用 D-02 方案测试账号（user001 等），保证演示路径可复现。

- 原型仅作参考，最终以 Element Plus 组件实现。
