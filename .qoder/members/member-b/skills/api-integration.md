# Skill (B专属): T5 契约接口对接

## Description

指导成员 B 按 T5 接口清单 v1.0 对接用户端接口（公共组 P-001~008 + 用户组 U-001~025）：Axios 封装、统一返回解包、错误码分支处理、分页约定、token 注入与登录态失效处理，确保与 `.qoder/rules/api-contract.md` 完全一致。

## When to Use

- W1：初始化 Axios 实例与请求/响应拦截器、Pinia user store
- W2-W5：每个页面接入接口前，确认该接口的封装方式与错误码分支
- 联调时接口异常排查（对照 T5 契约核对参数与响应字段）

## 统一返回解包规则（与 api-contract.md 一致）

```
HTTP 200 且 code == 200  → 成功，取 data（列表取 data.list + data.total）
HTTP 200 且 code != 200  → 业务错误，按 code 分支处理
code == 1002             → 清 token，跳 /login（全局响应拦截器处理）
其他 code                → ElMessage.error(message)（前端不翻译文案，只展示后端 message）
```

特殊文案（登录/注册页本地覆盖，其余统一用后端 message）：

| code | 本地文案 |
|------|----------|
| 2001 | 用户名已存在 |
| 2002 | 手机号已注册 |
| 2003 | 用户名或密码错误 |
| 2004 | 账号已被禁用 |

## Axios 封装要点

1. `baseURL: '/api'`；开发代理用 Vite `server.proxy` 指向后端（见 W1 任务书）。
2. 请求拦截器：从 Pinia/localStorage 取 token，注入 `Authorization: Bearer <token>`。
3. 响应拦截器：按上表解包；1002 时清登录态并跳转；业务错误抛给页面处理或统一 toast。
4. 提交类接口：页面侧按钮 loading 状态，请求未返回前禁用（后端 1006 幂等兜底）。
5. 分页参数固定 `{ page, pageSize }`（pageSize ≤ 100），响应取 `data.list` + `data.total`。

| code | 含义 | 页面处理 |
|------|------|----------|

## 审查清单

1. 接口 URL/方法/参数与 T5 完全一致，不增删字段
2. 响应解包只认 `{code, message, data, total}`，不依赖 HTTP 状态码做业务判断
3. 错误码分支覆盖 T5 该接口备注列全部主要错误码
4. token 过期/失效统一走 1002 流程
5. 分页固定 page/pageSize，列表取 data.list/data.total

## Output Format

按「接口 → 封装文件 → 错误码分支」三段输出；联调问题记录到 `docs/phase4/member-b/deliverables/` 对应任务文档的「联调记录」节。
# Skill (B专属): T5 契约接口对接

## Description

指导成员 B 按 T5 接口清单 v1.0 对接用户端 33 个接口（公共组 P-001~P-008 + 用户组 U-001~U-025）：统一封装 Axios 请求层、错误码分支处理、分页与 loading 模式，保证与后端契约零偏差。

## When to Use

- W1 初始化 Axios 实例与拦截器
- 每个页面绑定接口时
- 联调报错排查时（先核对 T5 契约，再找 A）

## Axios 封装要点

- baseURL：`/api`（vite proxy 转发到后端 8080）
- 请求拦截器：从 Pinia/localStorage 取 token，注入 `Authorization: Bearer <token>`（白名单接口不带亦可）
- 响应拦截器：
  - `code === 200` → 返回 data（分页接口返回 `{list, total}` 整体）
  - `code === 1002` → 清空 token，router.push('/login')，ElMessage 提示
  - 2001/2002（注册）、2003/2004（登录）→ 页面内做特殊文案
  - 其余 → `ElMessage.error(message)`，reject 供调用方兜底

## 联调排错顺序

1. 先核对 T5 契约：URL、方法、参数名、响应字段是否一致（不一致先查是否 A 升版）
2. 核对错误码含义（T3 表），确认是业务规则还是前端 bug
3. 后端日志（A 侧）确认请求是否到达、参数是否解析
4. 记录问题到联调记录：接口编号 + 现象 + 定位 + 决议，随交付物归档
